# Traductions et refus structurés

L’application choisit explicitement la langue. Form Guard ne lit ni `Accept-Language`, ni cookie, ni paramètre d’URL. Anglais et français sont fournis sans extension `intl` ni framework.

```php
$guard = new FormGuard\Guard([
    'scope' => 'contact',
    'locale' => 'fr-CA',
    'fallback_locale' => 'en',
    'messages' => [
        'fr' => ['too_fast' => 'Veuillez patienter {seconds} s.'],
        'de' => ['too_fast' => 'Bitte {seconds} s warten.'],
    ],
]);
```

Ordre de repli : locale demandée, langue de base, locale de repli configurée, langue de base du repli, puis anglais. Les locales ignorent la casse et assimilent `_` à `-`. Un catalogue partiel ne remplace que ses propres entrées. Une langue inconnue ne change pas la protection.

Les messages sont du **texte brut**, à échapper en HTML, y compris lorsqu’ils viennent d’un traducteur externe. `{seconds}` et `{retry_after}` sont des paramètres nommés simples. Pas de formatage ICU ni de pluriels dans cette version ; les secondes abrégées évitent cette difficulté dans les messages fournis.

## Codes de rejet

`Rejection::$reason` est un enum `RejectionReason`, indépendant du message :

| Valeur | Statut HTTP proposé |
| --- | --- |
| `form_unavailable` | 403 |
| `form_expired` | 403 |
| `invalid_token` | 403 |
| `honeypot` | 422 |
| `too_fast` | 422 |
| `invalid_signals` | 422 |
| `behavior_rejected` | 422 |
| `rate_limited` | 429 |

Utiliser `$error->reason->value` dans la logique et les journaux, sans analyser `$error->getMessage()`. Le statut reste accessible par `getCode()`. `parameters` ne contient que des informations de présentation sûres : secondes restantes et périmètre `client`/`ip`. Ni IP du visiteur, ni jeton, ni clé privée. `retryAfter` donne le délai du HTTP 429.

`form_unavailable` couvre un formulaire inconnu, consommé, malformé ou issu d’un autre périmètre ; un jeton absent ne permet pas d’en connaître tout l’historique. Plusieurs refus partagent volontairement un message générique. L’application peut afficher un message encore plus général tout en conservant le code en interne.

## Traducteur externe

Fournir un callable ou implémenter `FormGuard\Translation\TranslatorInterface` :

```php
$guard = new FormGuard\Guard(['locale' => 'fr'], translator: function (string $key, array $parameters, string $locale): ?string {
    // Déléguer au traducteur de l’application.
    // null, une chaîne vide ou la clé inchangée déclenchent le repli intégré.
    return null;
});
```

Le traducteur est appelé après libération du verrou et validation de la transaction de stockage. Le callable renvoie une chaîne ou null ; ses exceptions ne sont pas masquées. Paramètres et langue sont transmis explicitement. Les mêmes règles de repli s’appliquent à l’adaptateur d’interface.

Les `StorageException` techniques ont un diagnostic générique et un code `reason` stable non traduit destiné à l’exploitant. Ne pas les afficher telles quelles ; l’application choisit son message d’indisponibilité traduit.
