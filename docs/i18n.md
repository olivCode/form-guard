# Internationalization

The application chooses the language explicitly. Form Guard does not read `Accept-Language`, cookies or URL parameters. English and French are bundled; no `intl` extension or framework is required.

```php
$guard = new FormGuard\Guard([
    'scope' => 'contact',
    'locale' => 'fr-CA',
    'fallback_locale' => 'en',
    'messages' => [
        'fr' => ['too_fast' => 'Veuillez patienter {seconds} s.'],
        'de' => ['too_fast' => 'Bitte {seconds} s warten.'],
    ],
]);
```

Fallback order is the requested locale, its base language, the configured fallback locale, its base language, then English. Locale matching is case-insensitive and treats `_` as `-`. A partial catalogue only overrides its own entries. Unknown languages fall back without changing protection behavior.

Messages are **plain text**. Escape them for HTML output; do not treat an override or an external translation as trusted HTML. `{seconds}` and `{retry_after}` are simple named placeholders. This release does not implement ICU formatting or pluralization; abbreviated seconds avoid language-specific plural rules in the bundled messages.

## Stable rejection reasons

`Rejection::$reason` is a `RejectionReason` enum, independent of the rendered message:

| Value | Suggested HTTP status |
| --- | --- |
| `form_unavailable` | 403 |
| `form_expired` | 403 |
| `invalid_token` | 403 |
| `honeypot` | 422 |
| `too_fast` | 422 |
| `invalid_signals` | 422 |
| `behavior_rejected` | 422 |
| `rate_limited` | 429 |

Use `$error->reason->value` for application logic and logs. Do not parse `$error->getMessage()`. The suggested status remains available through `getCode()`. `parameters` contains only safe presentation metadata (remaining seconds and `client`/`ip` limit scope), never the visitor IP, token or runtime key. `retryAfter` remains the actual retry delay for HTTP 429.

`form_unavailable` covers unknown, consumed, malformed or different-scope forms; it does not pretend to distinguish the exact history of a missing token. Several bundled messages intentionally share generic text. Applications may further aggregate outward errors while recording the reason internally.

## Framework/application translators

Provide a callable or implement `FormGuard\Translation\TranslatorInterface`:

```php
$guard = new FormGuard\Guard(['locale' => 'fr'], translator: function (string $key, array $parameters, string $locale): ?string {
    // Delegate to your application's translator here.
    // Return null, an empty string or the unchanged key to use bundled fallback.
    return null;
});
```

External translators run after storage transactions release their lock. Callables must return a string or null; exceptions are not silently swallowed. Parameters and locale are passed explicitly. An interface adapter's unchanged key or empty result also falls back to the bundled catalogue.

Technical `StorageException` messages are deliberately generic diagnostics, with an untranslated stable `reason` for operators. They must not be returned to visitors verbatim; the application chooses its own localized temporary-failure message, as in the example.
